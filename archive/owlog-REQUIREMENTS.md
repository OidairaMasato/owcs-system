# OW Rank Log ／ 要件定義メモ（v0.1）

作成日: 2026-08-31

## 1. コンセプト

Overwatch 2 のランク戦の記録を自分で残し、推移を眺め、AI に振り返らせる **自分専用の戦績ノート**。

- 題材が趣味（OW）、目的は「毎日使う実用品」
- 楽しさ最優先。設計は軽く、作りながら育てる
- 飽きない条件 = **入力が数タップで終わること** と **見て気持ちいいグラフがあること**

## 2. 前提調査（重要）

| 項目 | 結果 |
|---|---|
| Blizzard 公式 API | OW2 は対象外（WoW / D3 / SC2 のみ）。**試合履歴 API は存在しない** |
| 試合単位のデータ | 自動取得は不可能 → **手入力が前提** |
| OverFast API（非公式） | キャリアプロフィールをスクレイピングする OSS。ロール別ランク・通算成績・ヒーロー別統計を取得可。v4.7.0（2026-06）でメンテ継続中、ホスト版 `overfast-api.tekrop.fr` あり |
| OverFast の制約 | Blizzard 側でキャリアプロフィールを **公開設定** にする必要あり。秒単位のレート制限あり（自分専用なら問題なし）。非公式のため仕様変更で壊れる可能性あり → **落ちても本体機能は動く設計にする** |
| コンソール対応 | OverFast は `platform=console` を有効値として受け付ける（実測確認済み）。コンソール専用アカウントでもランク取得の見込みあり |
| 未検証リスク | 日本語 BattleTag（マルチバイト）が Blizzard 側の検索・プロフィールURLで正しく扱われるか。公開設定後に要再検証 |

## 3. スコープ

### v1（まず動かす）
- セッション単位の記録（日付・ロール・戦績・RP 増減・コンディション・メモ）
- 試合単位の詳細記録（気になった試合だけ追加できる任意入力）
- ランク推移グラフ
- OverFast API による現在ランクの自動取得

### v2 以降
- 週次 AI レポート（Claude API による自動振り返り）
- マップ／ヒーロー別勝率
- やめどき分析（連戦数・時間帯・連敗後の勝率）
- 友達アカウント対応（マルチユーザー）

## 4. 機能要件

### 4.1 記録
- **セッション記録**（基本）: 日付、プレイ時間帯、ロール、試合数、勝敗数、開始／終了 RP・ティア、コンディション（気分・疲労・集中度）、フリーメモ
- **試合記録**（任意・使い分け）: マップ、モード、使用ヒーロー（複数）、ロール、勝敗、スコア、RP 増減、味方／敵構成、リプレイコード、反省メモ
- 入力はスマホで完結する UI を最優先（プルダウン・トグル中心、キーボード入力は最小限）
- 直前の入力値をデフォルト表示して連続入力を高速化

### 4.2 ランク自動取得
- BattleTag をキーに OverFast API を定期実行（1 日 1 回程度）＋手動更新ボタン
- ロール別（タンク／DPS／サポート）のティア・ディビジョンをスナップショット保存
- 取得失敗時は手入力値を正とする（フォールバック）

### 4.3 可視化（最優先の楽しさ担保）
- シーズン別のランク推移グラフ（ロール別に重ねて表示）
- 直近 N 試合の勝率、連勝／連敗の可視化
- ヒートマップ的な「プレイした日」カレンダー

### 4.4 週次 AI レポート
- 毎週決まった曜日にバッチ実行
- 先週分のセッション・試合・メモを集計 → Claude API に投げて所見コメントを生成
- 生成結果は DB に保存し、アプリ内で履歴として読める
- 通知手段（メール／画面のみ）は未定

### 4.5 認証
- v1 は自分だけだが、**将来の友達参加を見据えてマルチユーザー前提でデータモデルを作る**
- 全テーブルに user_id を持たせる。ログインは Spring Security ＋ セッション or JWT
- ソーシャルログインは後回し

## 5. データモデル案

```
users            (id, battle_tag, platform, display_name, created_at)
seasons          (id, name, started_on, ended_on)
sessions         (id, user_id, season_id, played_on, started_at, ended_at,
                  role, mood, fatigue, note)
matches          (id, session_id, seq_no, map_id, mode, role, result,
                  score_own, score_opp, rp_delta, tier, division,
                  replay_code, note)
match_heroes     (match_id, hero_id, play_ratio)
maps             (id, name, mode)
heroes           (id, name, role)
rank_snapshots   (id, user_id, fetched_at, role, tier, division, source)
weekly_reports   (id, user_id, week_start, summary_md, generated_at)
```

- ランクは `tier`（Bronze〜Champion）＋ `division`（5〜1）＋ RP で保持。仕様変更に備えて数値化した `rank_value` を派生カラムで持つと推移グラフが楽

## 6. 技術構成

| レイヤ | 採用 |
|---|---|
| バックエンド | Java 21 / Spring Boot 3（得意領域で速く作る） |
| DB | PostgreSQL ＋ Flyway |
| フロント | React ＋ TypeScript ＋ Vite、**PWA 化してスマホからホーム画面起動** |
| グラフ | Recharts 等 |
| ホスティング | 低コスト PaaS（Render / Fly.io / Railway のいずれか） |
| 外部連携 | OverFast API（ランク取得）、Claude API（週次レポート） |
| バッチ | Spring の `@Scheduled`（PaaS のワーカー枠を使わず本体プロセス内で完結） |

**コスト目安**: PaaS 0〜1,000 円／月＋ Claude API 数十円／月。シフト管理アプリの AWS 構成より大幅に安い。

## 7. 非機能

- スマホ入力: 1 セッションの記録を **30 秒以内** で終えられること（最重要指標）
- PC 閲覧: グラフと一覧をじっくり見られるレスポンシブ対応
- 可用性: 自分専用なので落ちてもよい。ただしデータは必ず守る（PaaS の自動バックアップ or 定期エクスポート）
- 外部 API 障害時も記録機能は無停止

## 8. 開発ステップ

1. **v1-a**: DB スキーマ ＋ セッション記録 CRUD ＋ 一覧（ローカルで動く）
2. **v1-b**: ランク推移グラフ。ここで「見て楽しい」を確認する
3. **v1-c**: PaaS デプロイ ＋ 認証 ＋ PWA 化。スマホから実運用開始
4. **v1-d**: OverFast API 連携
5. **v2**: 試合詳細記録の拡充 → マップ／ヒーロー別勝率 → 週次 AI レポート

※ 3 まで到達した時点で「毎日使える」状態になるのを最優先。

## 9. アカウント情報

- BattleTag: `おれまさと#3428`（API キー形式: `おれまさと-3428`、URL は percent-encoding が必要）
- プラットフォーム: コンソール

### 検証状況（2026-08-31 時点）

| 確認内容 | 結果 |
|---|---|
| `GET /players?name=おれまさと` | `{"total":0,"results":[]}` |
| `GET /players/おれまさと-3428/summary` | 404 |
| `https://overwatch.blizzard.com/ja-jp/career/おれまさと-3428/` | 404 |

**原因の第一候補はキャリアプロフィールが非公開のまま**（OW2 のデフォルトは非公開）。

> 注意: `account.battle.net/privacy` の「プロフィールの表示設定」は **Battle.net アプリ上のプロフィール**（カスタムステータス・プレイ中のゲーム・ソーシャル接続）の設定であり、Overwatch のキャリアプロフィールとは**別物**。ここを公開にしても API では取得できない（2026-08-31 実測、404 のまま）。
ゲーム内 `オプション` → `ソーシャル` タブ → `キャリアプロフィールの公開設定` を「公開」に変更後、再検証する。
公開後も 404 が続く場合、日本語 BattleTag が Blizzard 側で正しく扱われていない可能性を疑う（英数字の BattleTag への変更 or 手入力へのフォールバックを検討）。

## 10. 入力UIモック（2026-08-31）

セッション記録の入力フローを動くモックで検証。スマホで開いて実測できる。

- URL: https://claude.ai/code/artifact/e1d9c45b-7eed-4c6d-9cc3-5fe305972197
- 検証指標: **保存まで30秒以内 / 15タップ以内**（モック内のタイマーとタップカウンタで実測）
- 速さのための設計判断:
  - 日付は自動、入力させない
  - ロールはサポート（主ロール）を初期選択
  - 勝敗は大きなボタンを連打するだけ。試合ごとのマップ・ヒーローは v1 では聞かない
  - ランクは前回値から開始し、多くの日は RP の数字だけ直す
  - メモは折りたたみ（書きたい日だけ開く）
- 主ロールは **サポート / ダメージ**。タンクは 3番目。UI の初期値はサポート

## 11. データモデルの変更（2026-09-01 / V3）

「1日1ロール1件」の制約が実態に合わなかったため変更した。

- **1日に複数セッションを許す**。朝と夜は別セッション。並び順は `started_at`
- **RP は1試合ごとに持つ**（`session_matches.rp_delta`）。リザルト画面の増減をそのまま入れる
- セッションは開始ランクと終了ランクを持ち、終了ランクは各試合の増減を積み上げて算出する
- 入力UIは、勝敗ボタン1タップで既定の増減（勝 +22 / 負 −18）が入り、違った試合だけチップを叩いて直す形にした。
  1タップ／試合という速度は維持したまま、試合単位の粒度を得ている
